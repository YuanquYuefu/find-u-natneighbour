# nat-neighbour — NAT VPS 鄰居普查與活躍度探測工具

**v1.0.0** · 腳本：[nat.sh](nat.sh) · 項目約定：[project.md](project.md)

這是一個適用於各類 **KVM / LXC / OpenVZ** 架構 NAT VPS（「NAT 小雞」）的通用二層鄰居普查與活躍度分析腳本。只需透過一行 `wget` 指令下載，之後在終端機直接輸入 `nat`，即可自動完成 **「同區真實買家鄰居人數統計」** 與 **「鄰居即時活躍度 / 母雞外網擁擠度排行」** 兩段檢測。

---

## 一鍵安裝與使用

### 1. 下載並註冊 `nat` 快捷指令

在你的 LXC 或 KVM 機器終端機（SSH）中執行以下 `wget` 指令（請將 `<YOUR_GITHUB_USERNAME>` 替換為你的 GitHub 帳號）：

```bash
wget -qO /usr/local/bin/nat https://raw.githubusercontent.com/<YOUR_GITHUB_USERNAME>/nat-neighbour/main/nat.sh && chmod +x /usr/local/bin/nat
```

*(或者直接下載 `nat.sh` 執行：`wget -qO nat.sh https://raw.githubusercontent.com/<YOUR_GITHUB_USERNAME>/nat-neighbour/main/nat.sh && bash nat.sh`，腳本首次運行時也會自動將自己註冊到 `/usr/local/bin/nat`。)*

### 2. 日常執行

安裝完成後，隨時在終端機輸入：

```bash
nat
```

即可自動依序執行兩段檢測：
1. **【階段一】二層 ARP 鄰居普查與真實買家識別**（約 2 秒）
2. **【階段二】母雞外網負載基準與鄰居微延遲抖動活躍度排行榜**（約 5 秒）

## 命令列參數

| 指令 / 參數 | 行為說明 |
| :--- | :--- |
| `nat` | 預設模式：自動執行【階段一：鄰居人數統計】+【階段二：鄰居活躍度排行】 |
| `nat -q` 或 `nat --quick` | 快速模式：僅執行【階段一】，2 秒內輸出真實買家鄰居清單與總人數 |
| `nat -c 100` | 自訂階段二每台鄰居的高頻 Ping 採樣次數（預設 `50` 次，最少 `5` 次） |
| `nat -a` 或 `nat --all` | 將自動排除的老闆/母雞系統節點也一併納入階段二的活躍度排行榜 |
| `nat --uninstall` | 從系統中移除 `/usr/local/bin/nat` 快捷指令 |
| `nat -h` 或 `nat --help` | 顯示參數說明 |

## 核心機制與真實買家識別邏輯

### 1. 為什麼用二層 ARP 而不是單純看 Ping？
在同一台母雞的虛擬交換機（Linux Bridge / Open vSwitch / iKuai 內網段）下，所有同區鄰居位於同一個二層廣播域：
* 即使某位鄰居在系統內開啟了防火牆 **禁 Ping（阻擋 ICMP Echo）**，只要對該網段發送探測包，作業系統核心仍會在二層回應 ARP（`lladdr` MAC 位址）。
* 本腳本結合 **併發 ICMP 探測 + `ip neigh` ARP 表解析**，能 100% 抓出開啟禁 Ping 防火牆的「隱身鄰居」（標記為 `🛡️ 禁Ping(ARP在線)`）。

### 2. 如何自動區分「真實買家」與「老闆 / 母雞系統機」？
在 NAT 母雞網段中，除了真實買家外，往往還存在軟路由網關（如 iKuai / RouterOS）、母雞橋接介面、老闆手動開的測試機或 Looking Glass 探針機。腳本內建多維度啟發式過濾邏輯：

1. **預設路由與 Router 宣告排除**：
   自動讀取 `ip route` 預設網關（如 `.1`、`.254`）以及 ARP 表中帶有 `router` 標記的節點，歸類為 `網關/路由節點`。
2. **面板隨機 MAC（LAA）vs 母雞原生固定 OUI 比對**：
   * 現代財務與被控面板（如 Paymenter、Virtualizor、Convoy 等）自動開通買家 VM 時，通常會生成 **本地管理隨機 MAC（Locally Administered MAC，第一字節第二碼為 `2 / 6 / a / e`）**。
   * 而老闆在 Proxmox VE (PVE)、KVM 或 Xen 後台手動建立的軟路由、探針或測試機，則會帶有虛擬化官方固定 OUI（例如 PVE 的 `bc:24:11`、QEMU 的 `52:54:00`）。
   * 當腳本偵測到本機或同網段買家群聚使用 LAA 隨機 MAC 時，會自動將帶有母雞原生固定 OUI（如 `bc:24:11`）或實體硬體網卡 OUI 的機器識別為 **「老闆/系統手動機」** 並予以排除，不計入買家鄰居人數。
3. **純固定 OUI 環境的保留位識別**：
   若該商家所有容器/VM 統一使用相同廠商 OUI，腳本會進一步比對特殊管理尾號（如 `.2` 宿主橋接位、`.100` 整數探針位且 OUI 異於買家池），避免誤算系統節點。

### 3. 如何計算鄰居們的即時活躍度？（RTT Micro-Jitter Profiling）
在二層交換機環境下，單播流量雖受隔離無法直接嗅探，但同母雞小雞共享宿主 CPU 調度與虛擬網卡佇列：
* **💤 吃灰閒置（靜止）**：當鄰居 VM 無流量且 CPU 空閒時，連續 50 次錯峰高頻 Ping（間隔 `0.1s`）的回應延遲極度平穩，標準差（抖動 `mdev`）通常 `< 0.06 ms`。
* **⚡ 輕度活動 / 間歇連線**：當鄰居有間歇性請求或輕量背景任務時，`mdev` 與最大峰值 `max` 會出現輕微波動。
* **🔥 活躍跑流量中**：當鄰居正在拉大流量、看高畫質串流或高併發轉發時，`virtio-net` / `veth` 網卡軟中斷（softirq）排隊會導致回應延遲峰值跳升、抖動 `mdev` 顯著擴大（自動結合絕對閾值與當下網關基準倍數動態判定）。
* **🌐 外網基準對比**：自動從 `168.95.1.1`（台灣 HiNet）、`1.1.1.1`、`8.8.8.8` 中挑選距離最近的基準點同步採樣，對比內網網關與外網第一跳抖動差，即可得知當下整條母雞家寬是否被鄰居塞滿。
